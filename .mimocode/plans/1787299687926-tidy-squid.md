## 架构设计

### 第一步：分卷脚本（`scripts/split_shiji.py`）

把 `史记.md` 按"卷X 标题"分割成独立章节文件：

```
data/raw/shiji/
├── 卷001_五帝本纪.md
├── 卷006_秦始皇本纪.md
├── 卷047_孔子世家.md
├── 卷065_孙子吴起列传.md
...
└── manifest.jsonl  # {file, chapter, type, persons_mentioned, dynasty}
```

同时生成先秦人物候选清单 `data/candidates/pre_qin.jsonl`。

### 第二步：AI 提取器（`src/arcvita/extractors/classical_biography.py`）

**每个章节文件**交给 general subagent 提取，核心 prompt：

```
你是一位精通文言文的历史数据工程师。请从以下《史记》章节中提取人物的结构化传记数据。

输入：章节全文
输出：YAML 格式，包含：
1. 人物基础信息（姓名/字号/生卒/籍贯/朝代/原型）
2. 做事单元（每件事的起止时间/地点轨迹/阶段分解/结果/启发）
3. 名场面事件（成语出处/代表作/关键决策/至暗时刻）
4. 第一视角叙述（从原文中提炼或拟述主角口吻）

关键要求：
- 每个"做事单元"必须有完整的开始→过程→结束
- 地点用当时地名（可标注今地名）
- 日期用公元纪年（BCE用负数）
- 名场面标注 highlight_type: 成语/代表作/战役/决策/至暗时刻
```

**输出格式**（对接现有 models.py）：
```yaml
person:
  name_zh: "孙武"
  name_en: "Sun Tzu"
  birth_date: "约-544"
  death_date: "约-496"
  birth_place: "齐国乐安"
  era: "春秋"
  archetype: "兵法型"
  dilemmas: ["怀才不遇", "被误解"]
  summary_zh: "..."
  summary_first_person: "..."
  lesson: "..."
endeavors:
  - title_zh: "《兵法》十三篇与吴宫教战"
    start_date: "约-512"
    end_date: "约-512"
    places: ["齐国", "吴国", "姑苏台"]
    phases:
      - name: "献书"
        start_date: "约-512"
        end_date: "约-512"
        place: "吴国"
        highlight: "以兵法见吴王 — 转折点"
      - name: "教战"
        start_date: "约-512"
        end_date: "约-512"
        place: "姑苏台"
        highlight: "吴宫练兵斩姬 — 名场面，成语诞生"
    outcome: "《孙子兵法》传世，吴国霸业"
    lesson: "..."
events:
  - date: "约-512"
    place_name: "吴国"
    event_type: "创作"
    title_zh: "献《兵法》十三篇"
    is_highlight: true
    highlight_type: "代表作"
    highlight_note: "兵学圣典诞生"
```

### 第三步：批量调度（`scripts/extract_pre_qin.py`）

```
manifest.jsonl (先秦章节)
    ↓ 按章节分 batch (每 batch 3-5 章，约 50-100KB 文本)
    ↓ 每 batch 交给 1 个 general subagent
    ↓ subagent 逐章节：read → 提取 → write YAML
    ↓ 结果写入 data/extracted/pre_qin/
    ↓ 同名人物自动合并（孙武+伍子胥 in 同一列传 → 2 人）
```

先秦预计 20-30 个 batch（50-80 人），单 subagent 处理 3-5 章。

### 第四步：合并入库（`src/arcvita/merge.py`）

```
data/extracted/pre_qin/*.yaml
    → 规则校验（生卒年/地点/事件数）
    → 去重（姓名+朝代）
    → 评分（信息密度排序）
    → data/curated/classical/pre_qin/
    → 合并到 persons.yaml + events.yaml + endeavors.yaml
    → 重建 biography.db + site/
```

与现有 pipeline 对接：`config.yaml` 加 `sources.classical`，pipeline 在 enrich_offline 后读取 extracted YAML。

## 执行步骤（Build 阶段）

### Step 1：分卷 + 建候选清单
1. `scripts/split_shiji.py` — 分割史记.md → 章节文件
2. 人工/AI 标注先秦章节 → `data/candidates/pre_qin.jsonl`

### Step 2：AI 提取 MVP（5 人验证）
1. 选 5 个先秦人物（孙武/商鞅/勾践/屈原/荆轲）
2. `extractors/classical_biography.py` 实现 prompt
3. 1 个 subagent 跑 5 章 → 落盘 YAML → 与维基比对

### Step 3：全量先秦提取（30-50 人）
1. `extract_pre_qin.py` 批量调度 subagent
2. 合并入库 + 重建 site/
3. 验证 HTML 时间轴

### Step 4：扩展到秦汉（可选后续）
- 汉书/后汉书/三国志 的列传
- 同样流程，只需改 manifest 范围

## 风险与对策

| 风险 | 对策 |
|---|---|
| 史记单文件 7MB+，subagent 读不完 | 分卷脚本先切割，每章独立文件 |
| 文言文 LLM 提取偏差 | 5 人 MVP 验证后再扩；多源交叉 |
| 人物价值参差 | 加 scoring 低分进 review |
| 同名（如多个"公子"） | 按世家/列传上下文区分 |

## 验证计划
- 5 人 MVP：孙武/商鞅/勾践/屈原/荆轲，与维基百科/史记原文比对
- 先秦全量：30-50 人，事件数 > 150，名场面 > 20
- HTML 时间轴：先秦人物在庞加莱图上正确显示（公元前区域）
